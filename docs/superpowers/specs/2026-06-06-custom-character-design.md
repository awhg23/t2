# 自定义人物独立创建设计

## 背景

当前项目已经有两条相邻但边界不够清晰的能力：

- `管理灵瑞` 页中的“上传图片自定义”，允许用户上传图片并直接创建自定义灵瑞。
- `服饰工坊` 页中的服饰生成，允许当前灵瑞基于参考图生成穿搭形象。

这两条能力会让“人物创建”和“服饰创建”在感知上混在一起。用户现在提出的新目标是：

- 自定义人物需要和自定义服饰严格分开。
- 创建人物时，生成结果必须严格参考初始五位宠物的美术风格。
- 自定义人物应当成为后续聊天、成长、上传、服饰工坊的基础角色，而不是一次性图片效果。

本设计聚焦“自定义人物创建”这一条能力，不改动服饰工坊的独立定位。

## 目标

- 新增一条独立的“自定义人物”创建能力。
- 支持用户上传人物参考图创建角色。
- 生成出的角色保持与初始五位宠物一致的美术体系：
  - Q 版
  - 柔和配色
  - 校园手账感
  - 贴纸式轮廓
  - 透明背景
- 创建完成后，人物以自定义灵瑞的形式进入现有灵瑞列表。
- 后续服饰生成继续基于该人物基础形象进行，不在人物创建阶段混入服饰逻辑。

## 非目标

- 不在本期支持“人物创建时同步生成服饰”。
- 不做多人物合影拆分。
- 不做局部重绘、换脸或精细人脸编辑。
- 不做完全自由画风切换。
- 不改变现有服饰工坊的入口和能力边界。

## 用户流程

### 创建人物

用户进入 `管理灵瑞` 页，在新的“自定义人物”区域完成以下步骤：

1. 上传人物参考图。
2. 输入人物名字。
3. 输入一句人物气质描述。
4. 选择偏向哪一只初始灵瑞的人格底色，默认使用推荐选项。
5. 点击“创建自定义人物”。

系统返回：

- 一个已经灵瑞化的人物基础形象
- 基础人格设定
- 开场白
- 对话风格

创建完成后，该人物自动加入灵瑞列表并切换为当前激活角色。

### 后续服饰

用户若要给该人物换装，仍进入 `服饰工坊`，沿用现有服饰生成逻辑：

- 人物创建只负责“基础角色”
- 服饰工坊只负责“换装”

这样可以保持人物和服饰的边界稳定。

## 信息架构调整

`管理灵瑞` 页调整为三块能力区：

1. 预设与已有灵瑞列表
2. 自定义人物创建
3. 名人灵瑞生成

现有“上传图片自定义”会被“自定义人物创建”替代或重命名，避免继续使用“上传图片自定义”这种模糊表述。

推荐文案：

- 区块标题：`自定义人物`
- 区块副标题：`上传参考图，生成同五灵瑞画风的人物形象`
- 提交按钮：`创建人物基础形象`

服饰页文案保持为“服饰工坊”，不再承担人物创建职责。

## 输入与输出

### 前端输入

最小输入集合：

- `referenceImage`
- `name`
- `personaHint`
- `styleBasePet`

字段说明：

- `referenceImage`：用户上传的人物参考图，必填。
- `name`：人物名称，必填。
- `personaHint`：一句人物气质描述，选填但推荐填写。
- `styleBasePet`：人物偏向哪只初始灵瑞的风格底色，默认值建议为 `guardian` 或 `wisdom`。

### 后端输出

接口返回统一结构：

```json
{
  "ok": true,
  "provider": "model-character-image",
  "pet": {
    "name": "小峰",
    "type": "守护型",
    "opening": "我来了，今天也一起慢慢变好。",
    "personality": "稳定、认真、会陪伴，也会提醒你把节奏放稳。",
    "tone": "温和具体，像熟悉的朋友一样说话。",
    "styleBasePet": "guardian",
    "imageUrl": "/assets/generated/characters/character-xxx.png"
  }
}
```

返回结果最终仍会被标准化后写入 `state.customPets`，这样现有系统中的聊天、成长、上传和服饰逻辑可以继续复用。

## 生成策略

### 核心原则

人物创建的重点不是“生成一张像真人的图”，而是“把人物参考图转译成初始五宠同一体系下的灵瑞化人物角色”。

因此生成策略采用“两层约束”：

1. 人物识别约束：只吸收人物的公开可见特征
2. 五宠风格约束：强制锁定统一画风

### 人物识别约束

允许保留的特征：

- 发型
- 脸型的大致轮廓
- 眼镜等公开配饰
- 气质倾向
- 衣着大轮廓

不追求：

- 写实相似度
- 精准人脸复刻
- 真人照片感

### 五宠风格约束

后端新增专用的人物生成 prompt 模板，不复用服饰生成模板。模板必须明确写死这些要求：

- 参考初始五位宠物的统一美术体系
- 柔和、可爱、Q 版、贴纸感、校园手账感
- 透明背景
- 单角色全身
- 统一线条粗细和配色柔和度
- 禁止写实、厚涂、3D、照片感、偏日漫写实风

如果提供 `styleBasePet`，则在统一画风的基础上再加入细分人格调性：

- `guardian`：更稳、更暖、更安抚
- `vitality`：更明亮、更元气
- `wisdom`：更清爽、更理性
- `healing`：更柔软、更治愈
- `wonder`：更梦幻、更灵感化

## 与服饰工坊的解耦

### 人物创建阶段

人物创建阶段只产出：

- 基础形象
- 基础人格
- 可聊天的基础角色

不产出：

- 多套服饰
- 服饰描述
- 穿搭分类

### 服饰工坊阶段

服饰工坊继续读取当前激活人物的 `img` 作为参考图输入。

因此系统行为变为：

- 先创建人物
- 再基于人物生成服饰

这样既避免能力重叠，也能确保服饰生成围绕同一个基础角色持续展开。

## 前端改动

### `index.html`

需要调整 `管理灵瑞` 页中的现有表单结构：

- 将“上传图片自定义”重命名为“自定义人物”
- 表单字段调整为：
  - 人物参考图
  - 人物名字
  - 人物气质描述
  - 风格基底选择
- 按钮文案改为“创建人物基础形象”

### `app.js`

新增或调整以下逻辑：

- 新的表单提交流程 `createCustomCharacter()`
- 新的人物标准化逻辑 `normalizeCharacterInput()`
- 结果写入 `state.customPets`
- 创建成功后自动切换当前激活角色

现有 `generateOutfit()` 不改语义，只继续以当前激活角色图作为 reference image。

## 后端改动

### 新接口

新增接口：

- `POST /api/pets/custom-character`

请求体：

```json
{
  "referenceImage": "data:image/png;base64,...",
  "name": "小峰",
  "personaHint": "安静、可靠、像会提醒我学习的朋友",
  "styleBasePet": "guardian"
}
```

### 后端处理流程

1. 接收人物参考图。
2. 用大模型生成角色设定 JSON。
3. 用专用人物生成 prompt 生成基础人物形象。
4. 将人物图持久化到生成目录。
5. 返回结构化人物信息。

### 文件输出

推荐新增目录：

- `assets/generated/characters/`

用于存放人物基础形象，避免与服饰生成目录混用。

## 失败兜底

如果模型文字设定失败：

- 使用本地默认人格模板兜底

如果模型图片失败：

- 使用对应 `styleBasePet` 的默认角色图作为临时兜底
- 同时保留人物名字和人格设定，保证创建流程不至于中断

兜底目标不是“像用户上传的人”，而是“仍然处于正确画风体系，并保持流程完整可用”。

## 风险与约束

### 风格漂移

风险：

- 参考图过强时，模型可能偏向写实人物风

应对：

- 统一使用独立的人物生成 prompt
- 明确负向约束
- 必要时固定一张五宠风格参考图作为美术锚点

### 人物与服饰耦合回潮

风险：

- 如果人物创建结果里混入服饰描述，后续用户会误解为“人物创建和服饰是一件事”

应对：

- 前端文案和按钮语义保持清晰
- 后端接口输出不包含服饰字段

### 自定义人物数据兼容

风险：

- 现有 `state.customPets` 主要服务于“自定义灵瑞”和“名人灵瑞”

应对：

- 新人物创建仍然复用 `state.customPets`
- 通过 `source` 字段区分 `user-character`、`user-custom`、`model-celebrity`

## 验证方案

最少需要完成以下验证：

1. 上传人物参考图后，能创建基础人物并加入灵瑞列表。
2. 新人物可以正常被切换为当前角色。
3. 新人物可以参与聊天。
4. 新人物可以进入服饰工坊继续生成服饰。
5. 图片生成失败时，仍能创建一个正确画风的兜底人物。
6. 多次创建人物后，灵瑞列表和本地状态保持稳定。

## 推荐实施顺序

1. 新增后端 `custom-character` 接口
2. 抽离人物生成专用 prompt
3. 新增 `assets/generated/characters/` 持久化逻辑
4. 替换前端“上传图片自定义”为“自定义人物”
5. 接入 `styleBasePet` 选择
6. 跑通人物创建 -> 切换 -> 聊天 -> 服饰工坊全链路验证

## 最终建议

本期推荐采用以下落地策略：

- 创建方式：仅支持“上传人物参考图”
- 页面入口：放在 `管理灵瑞`
- 角色定位：基础人物形象
- 与服饰关系：严格分开
- 画风策略：统一锁定初始五位宠物的美术体系

这是当前风险最低、用户感知最清晰、也最利于后续扩展的一条路径。

# 宠物返图标注与文案优化设计

## 背景

当前宠物返图已经具备“识图后返回可爱批注图”的能力，但存在两个直接影响观感的问题：

- 标注位置使用固定坐标，容易出现箭头和文字像是在“随便指一块地方”，与画面主体关系弱。
- 文案主要由 `tags`、`feedback` 直接截断拼接，容易出现“像标签堆叠”或“像硬凑短句”的感觉。

在上一轮改动里，底部大卡片已经移除，返图遮挡问题下降了；这一轮聚焦继续提升“看起来更合理、更像宠物在轻声批注”的体验。

## 目标

- 让标注更像贴在画面边缘的轻量手账贴纸，而不是横穿主体的大块说明。
- 让文案从“标签裁切”升级为“有语义的小观察”。
- 保持现有返图接口、存储方式和前端展示结构不变。
- 继续保证没有模型时也能返回可接受的本地兜底效果。

## 非目标

- 不做真正的目标检测、分割或视觉定位。
- 不新增前端编辑标注位置的交互。
- 不改动上传分析页的整体信息架构。
- 不恢复已删除的底部大卡片。

## 设计方案

### 1. 文案结构改为固定语义槽位

返图文案不再把 `tags` 简单当作 3 条标注直接使用，而是统一组织为：

- `title`：这张图的小标题，像手账页签。
- `headline`：一句总评，表达宠物对当前画面的轻反馈。
- `callouts[0]`：画面中的主要对象或动作。
- `callouts[1]`：环境、氛围或细节观察。
- `callouts[2]`：情绪感受或为什么值得记住。

这样可以保证三条标注分别承担不同角色，减少三个短句语义重复或全部像标签名的问题。

### 2. 模型提示词收紧输出要求

`createAnnotationPlan()` 继续用现有图片 + 识图结果生成 JSON，但提示词增加以下约束：

- `callouts` 不是标签词，而是像手写批注一样的自然短句。
- 优先描述“看到了什么”和“为什么想记住”，少用抽象名词。
- 避免命令式口吻、打卡口吻、总结汇报口吻。
- 避免“学习感 / 治愈时刻 / 值得记录”这类泛化占位词，除非没有更多信息可用。

## 3. 本地兜底文案改为语义生成

`fallbackAnnotationPlan()` 不再直接返回：

- `tags[0]`
- `tags[1]`
- `tags[2]`

而是按“对象 / 氛围 / 感受”三个槽位进行拼装：

- 对象优先来自 `event` 和首个高相关 `tag`
- 氛围优先来自 `category` 和次级 `tag`
- 感受优先来自 `emotionSignals` 或 `feedback`

如果识图信息很弱，则兜底成更自然的短句，例如：

- `今天这一幕`
- `光线刚刚好`
- `想把它记下来`

而不是只剩下类别词。

## 4. 标注布局改为边缘轻贴纸

`cuteOverlaySvg()` 的布局从“固定大跨度箭头”改为“边缘三点轻标注”：

- 标题区仍保留在左上，但整体高度收紧。
- 第一条标注放在左下偏边缘，避免压在主体中央。
- 第二条标注放在右上靠内边缘，作为环境观察。
- 第三条标注放在右中或右下偏边缘，作为情绪收束。
- 箭头缩短，更多是提示性弯线，不穿过画面大面积区域。

核心原则：

- 中央主体区域尽量留白。
- 标注块优先贴边。
- 没有底部整块承载区。

## 5. 保守适配不同尺寸图片

不引入复杂识别的前提下，布局使用更保守的相对坐标：

- 横图时，标注尽量分散在左右边缘。
- 竖图时，标题上移，第三条标注避免过低压边。
- 小图时自动减少字号和箭头长度，防止挤在一起。

这一步只做基于宽高比的轻量分支，不做内容识别。

## 数据流

现有链路保持不变：

1. 前端上传图片到 `/api/images/analyze`
2. 前端再调用 `/api/images/annotate`
3. 服务端生成 `plan`
4. 服务端把 SVG 覆盖到原图后持久化
5. 前端展示新的返图结果

本次仅替换第 3、4 步的生成规则。

## 错误处理

- 模型文案解析失败时，回退到新的语义化本地兜底。
- 任一字段超长时继续使用已有 `cuteShortText()` 和 `wrapCuteText()` 截断保护。
- 如果某个槽位缺信息，优先填自然短句，不回退成生硬标签。

## 验证方式

- 生成至少 1 张新的宠物返图，确认底部卡片已消失。
- 检查三条标注文案是否语义有区分，不再都是标签词。
- 检查箭头和文字是否主要停留在边缘区域，没有明显横穿主体。
- 确认 `/api/images/annotate` 仍能正常返回并落盘。

## 涉及文件

- `server.js`
  - `fallbackAnnotationPlan()`
  - `createAnnotationPlan()`
  - `cuteOverlaySvg()`
- 视需要复用现有前端展示，无需新增前端结构改动。
